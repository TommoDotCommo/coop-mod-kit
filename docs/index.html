Co-op Launcher Standard

One way of installing, hosting, joining and setting up, shared by MDK2 Co-op and The Witness Co-op, and the template for the next mod. Each game keeps its own look. What is shared is where things are, what they are called and how they behave. Friends find each other without typing IP addresses.

02

What the research says

Tailscale will never show a LAN list on its own

It carries no broadcast or multicast, so classic "LAN games" discovery comes up empty over it. But every device on the tailnet, including PCs friends have shared with you, is listed locally with its 100.x address and an online flag. The launcher can read that list and ask each online device directly. That is the auto-scan you want.

Tailscale forum · ipnstate (status JSON)
Shared Tailscale machines answer but cannot call out

A machine shared into a friend's tailnet is quarantined: it accepts connections and cannot start them. That suits a host/client game. The host shares their PC, friends join. If both people want to host, they share both ways. The launcher's help text has to say this in one line.

Tailscale: sharing
Windows broadcasts on one adapter only

A packet to 255.255.255.255 leaves only through the adapter with the preferred route. With Wi-Fi plus ZeroTier, Radmin or Hamachi, half the games stay invisible. The fix is to send a directed broadcast on each adapter's own subnet. Then L2 VPNs like ZeroTier work too.

WinIPBroadcast · ZeroTier forum
Good co-op games layer the ways in

Stardew Valley lists Steam friends' farms on the join screen by itself, takes an invite code, and keeps join-by-IP for LAN. Factorio has a LAN browser plus "Connect to address". Minecraft hosts announce on LAN every 1.5 s. Typing an address is always the fallback, never the main path.

Stardew wiki · Factorio wiki · LAN Announcer
Discord only makes web links clickable

Custom links such as steam:// show as plain text in Discord, where most invites get pasted. An invite has to be an https:// link, or a code the launcher picks up from the clipboard.

Discord support thread
UPnP helps, except behind CGNAT

UPnP and NAT-PMP only configure your own router. When the ISP shares one address between customers (a WAN address in 100.64.0.0/10), no setting at home opens a port. The launcher can detect this and say so plainly, then point to Steam or Tailscale.

RFC 6970 · CGNAT detection
The firewall prompt silently breaks VPN hosting

The first-run Windows Firewall prompt allows Private networks only. Tailscale tries to mark its adapter Private and sometimes fails; other VPN adapters start out Public. Friends then cannot reach the host and nothing says why. Setup should add the rule for both profiles once, and the lobby should check it.

Tailscale docs · Tailscale forum
Players resent launchers that add steps

The complaints repeat: a second Play button, silent failures, repeated permission prompts. Owlcat pulled its Rogue Trader launcher within a day. Ours earns its place only if it is faster than going without it: one click to rejoin, choices remembered, skippable, and every failure says what to do.

PC Gamer · Aftermath
Later: relayed play for GOG and Epic copies

Epic Online Services offers peer-to-peer with relays and a device-ID login that needs no Epic account, which could give non-Steam players Steam-like "no setup" joining. It needs a free developer registration and a check of the SDK licence. Not for the beta.

Epic: Connect interface

04

The standard

Rule IDs are stable, for docs and issues. "Must" rules apply to every co-op mod; game-specific content goes in the marked slots.

A. Structure

  • Four tabs, in this order and with these names: Play, Saves, Settings, About. Nothing else is top level.

  • Play holds your name, three tiles (Host a game, Join a friend, Play solo) and one primary button whose label says what it does: Open lobby, Join Fox, Play solo. The last choice is remembered.

  • Hosting or joining turns Play into the lobby. The other tabs stay usable while you wait. Leaving the lobby returns to the tiles.

  • A Rejoin shortcut appears on Play when the last host you played with is online: one click, no list.

  • The launcher can be skipped (MDK2: "Show launcher at start", hold Shift to bring it back). The Witness keeps its launcher program, and a shortcut flag starts the last choice directly.

  • Keyboard works everywhere: Enter confirms, Esc goes back, Tab moves, F1 shows the quick guide. Where the launcher runs inside the game (MDK2), the gamepad works too: A, B, and the bumpers switch tabs.

B. Finding each other

The joiner's launcher looks everywhere at once and lists what answers. The host does nothing special. All probes use one small query and answer, generalised from MDK2's existing CPQ1/CPS1 probe, so no traffic flows when nobody is looking.

  • Local network and L2 VPNs: a directed broadcast on every IPv4 adapter's subnet, to the game's default port and the next three. Never only 255.255.255.255.

  • Tailscale: if Tailscale is installed, read its local peer list (tailscale status --json, no window) and probe each online peer's 100.x address on the same ports. Shared-in machines are included. Nothing is sent anywhere else.

  • Steam friends: when the game runs from Steam, friends whose rich presence shows this mod's lobby are listed, and Steam's own "Join game" works.

  • Recent hosts: every successful join is remembered by itself (name, the route that worked, when). Recent hosts are probed and shown with live status. They replace MDK2's hand-made "Saved addresses"; rename, pin and forget stay as row actions.

  • Each row shows the host's name, the lobby state (in lobby, in game, full), players out of the limit, the route (LAN, Tailscale, Steam friend, Internet, Recent) and the ping. A different version is shown greyed, with the version, instead of being hidden.

  • The list starts filling the moment Join is chosen and refreshes every 5 s while it is on screen. The sources are named with a tick as each finishes, so an empty list explains itself.

  • Below the list, one box accepts any invite code, invite link, Steam lobby number, address, address:port, host name or Tailscale name. It says what it recognised before you press Join.

  • When the launcher gains focus and the clipboard holds an invite for this game, it offers it: "Fox's invite is on your clipboard. Join?" The clipboard is read only for that check and never stored or sent.

  • The host chooses who can see the lobby: Open to my networks (listed and joinable without a code on LAN and Tailscale) or Invite only (not listed; the invite's code is required). Steam lobbies stay friends-only either way.

C. Hosting and the invite

  • The lobby's Friends can join by panel lists every way in with a check result: Steam, local network, Tailscale (with this PC's Tailscale name), Internet, and Windows Firewall. Each failed check names its fix.

  • While a lobby is open, the launcher asks the router for the port by UPnP or NAT-PMP and removes the mapping when the lobby closes. If the router's WAN address is private or in 100.64.0.0/10, it says the ISP shares the address and internet invites cannot work.

  • Copy invite copies a short message with an https:// link and the code. The code carries every working route (LAN, Tailscale, internet, Steam lobby), the port and the lobby's secret. The internet address is included only when the internet check passed.

  • The joiner tries all routes in the code at once and keeps the first that answers, preferring LAN, then Tailscale, then internet when several answer within 300 ms.

  • The link opens a static page that reads the code from the part after #, so it never reaches a server. The page offers "Open in launcher" (a <mod>-coop:// link registered by Setup), the code to copy, and a download link for people who do not have the mod yet.

Invite code v1   <GAME>-XXXXX-XXXXX-...   (Crockford base32, groups of 5, case-insensitive)
  byte 0        version (4 bits) | flags (4 bits: has-steam, invite-only, ...)
  bytes 1-4     lobby secret (u32)
  bytes 5-6     port (u16)
  then n x 5    route kind (1 LAN, 2 Tailscale/VPN, 3 internet) + IPv4
  [8 bytes]     Steam lobby id, when has-steam
  last byte     CRC-8; any change makes the code invalid ("this code is incomplete")
Example        WIT-8M2KQ-7XR4D-0PZ9T-HV3CE-91A0G    LAN + Tailscale + internet, about 30 characters
Message        Fox is hosting The Witness co-op. Join: https://<pages>/join#WIT-8M2KQ-7XR4D-0PZ9T-HV3CE-91A0G

D. Lobby

  • Three columns: players (host marked, ready state, ping, speaking light, per-player mute), chat, and on the right Friends can join by above What to play.

  • What to play is a game slot, chosen by the host and shown read-only to the others: MDK2's level and checkpoint or save; The Witness's mode, race goal and parts of the map done.

  • The host's button reads Start game and starts once everyone is ready; until then it shows who it is waiting for. Others see Ready / Not ready. Leave is always one click.

  • Voice in the lobby follows the Voice settings (push to talk or open mic). Mute myself and deafen are on the players column.

  • When the game ends, everyone returns to the same lobby with the result shown in chat.

E. Settings

Settings is a list of sections down the left with rows on the right. The sections, their order and the shared rows are fixed; each game adds its own rows in the right section.

  • Every change is saved at once. Each section has "Reset section".

  • A row the host decides carries a host decides tag. In a lobby, a guest sees the host's value, greyed.

  • Numbers use sliders with units, choices use choosers, keys use press-a-key capture that refuses duplicates and F1. No typed numbers except the port.

  • The same setting has the same name in the launcher, the in-game menu and the quick guide.

F. Saves, About and messages

  • Saves lists co-op saves with who played, progress and when, then a New game slot (MDK2: level and checkpoint; The Witness: parts of the map done). Actions: Host this save, Play solo, Back up, Delete (asks once, in the page).

  • About holds the version, updates (check now, install, roll back, auto-check), the quick guide, Report a problem, links and credits.

  • An available update shows as a banner on Play with Update and What's new. Updating never interrupts a lobby or a running game.

  • Every failure message says what happened, names the person or setting involved, and offers the next step as a button: Try again, Update, Fix firewall, Send diagnostics.

G. Setup

  • Setup finds every install it can (Steam libraries, GOG, Epic manifests, the Overhaul build) and shows them as cards with a build check. Browse is the fallback.

  • One state-driven button, as both Setups already have: Install, Update, Repair, Up to date, Needs attention. Uninstall restores the originals and keeps saves.

  • Three ticked options before Install: desktop shortcut; allow hosting through Windows Firewall on Private and Public networks (one admin prompt); open invite links in the launcher (current user only, no admin). Uninstall removes all three.

  • The last screen has Play as its primary button.

What stays per game. Art, colours, fonts and wording tone; the What to play and New game slots; game-specific rows inside the fixed sections; the in-game overlay. A new mod copies the structure and fills the slots.

In the game: keys, menus and the HUD

The same thinking, applied once the game is running. Today the two mods give the same key different jobs: B is push to talk in MDK2 and ink colour in The Witness; H is the emote wheel in one and the voice channel in the other. Ping, push to talk and the emote wheel sit on different keys in each. A player who moves from one mod to the other has to relearn the basics.

MDK2's co-op keys follow common conventions and are the more settled set, so they become the standard. The Witness moves to match. Keys that only one game needs (revive, character wheel, drawing, radio, sky TV) stay with that game, off the shared keys.

H. Keys and controller

  • The shared co-op keys above have the same default in every mod. A new mod starts from this set.

  • A game's own co-op actions may use any other key, never a shared key, and never a key the game itself uses in any of its control presets.

  • Holding opens and releasing acts for wheels, talking, the player list and the guide. Toggles are a single press. This is the same in every mod.

  • Every key can be changed on the Controls page with press-a-key. Conflicts are checked within the groups of actions used together, as MDK2's Controls page already does. F1 is fixed.

  • The quick guide, the Controls page and the launcher read the same binding table, so they never disagree. The Witness already works this way; parts of MDK2's guide are hand-written and will be generated.

  • Controller: every co-op action works from a pad. The full rules are in section K below.

I. Menus and the HUD

  • One Co-op entry in the game's options menu, with the same sections and names as the launcher's Settings, plus a Session page: players, invite friends, copy invite, save now (host), leave. MDK2 has this as Options > Co-op; its pages are renamed to match.

  • The Witness has no in-game settings today; changes are made in the launcher and need a restart. For the beta its player list (now F5) becomes the hold-Tab panel with the session actions, and the toggles that are cheap to apply live (voice volumes, name tags, partner picture) move there. Everything else stays in the launcher, marked "applies next start".

  • The player list has one row per player: colour, name, host mark, ping, a speaking light, and where they are (area or distance) or their state (loading, down, watching). With the mouse: mute, volume, watch, and for the host, kick.

  • Screen zones: the player strip at top left; short notices at top centre (joined, left, saved), at most three, gone after 4 s; chat at bottom left; at bottom centre, banners that need an answer or a wait (vote to skip, reconnecting, waiting for players). Name tags, pings and typing dots live in the world. Each game lists the areas its own HUD uses, and co-op stays out of them.

  • One colour per player, everywhere: lobby, name tag, chat name, ping, ink and outline. It is given in join order from a palette that reads on both light and dark scenes. Players can change it under Players and interface.

  • The same words in every mod for the same events: "Fox joined", "Fox left", "Lost Fox, waiting up to 30 s", "Reconnecting to Fox", "Fox has a different version (v0.4.0)". One shared wording file, as the launcher messages have.

  • Esc never leaves a co-op game without one confirmation that says what happens: "The others keep playing", or for the host, "Everyone returns to the lobby". The game keeps running behind any co-op menu, and the menu says so.

  • Text stays readable at 1280 x 720 and scales with the window. The Witness already has a test that checks text size and that every button is on screen; both mods run it.

06

Mod managers and loaders

Many players will never run our Setup. They will install through Vortex from Nexus, through Mod Organizer 2, through a Linux tool like Lutris or Heroic, or by unzipping into the game folder. All of these work the same way: they copy files into place, and later remove exactly the files they copied. So the standard is one sentence. Copying the package's files must be a complete install, removing them must be a complete uninstall, and the mod must still know what it is and who installed it. Setup stays the friendliest route, but it must never be the only one.

Managers copy files, nothing more

Vortex deploys a mod by hard-linking the archive's files into the game folder, mirroring the archive's folders, and can deploy to the game's root. A game it knows nothing about needs a small game extension; neither MDK2 nor The Witness has one today. Nexus reportedly stopped work on its newer cross-platform app in 2026 and is focusing on Vortex.

Vortex extension example · GamingOnLinux
Writing into the game folder causes trouble

When a running program changes a file a manager deployed, Vortex breaks the link and asks the player about "external changes" at the next deploy. Players lose files by picking the wrong answer. Mod Organizer 2 diverts such writes to its overwrite folder instead.

Vortex wiki: external changes
Mod Organizer 2 adds games through a plugin

A new game is a short Python file in MO2's basic_games plugin. Files that must sit in the game's root folder, such as proxy DLLs, need the Root Builder plugin.

basic_games · Root Builder
Proxy DLLs share a small set of names

Ultimate ASI Loader, the common loader for "drop-in" fixes, works as dinput8.dll, dsound.dll, winmm.dll, version.dll and others. Two mods using the same name overwrite each other unless one loads the other.

J. Rules

  • Drop-in package. The release zip's files sit at the paths they take in the game folder. Copying them is a full install; deleting them is a full uninstall. No step renames, edits or patches a file the game ships. Anything the mod needs outside the game folder, it sets up itself at first start and copes with being removed.

  • Proxy a system DLL the game imports but does not ship, and load the real one from the Windows system folder, as MDK2's dinput8.dll does. Prefer a name graphics tools do not use: not dxgi or d3d11, which ReShade, Special K and DXVK take. For The Witness, winmm.dll or dsound.dll qualify: the game imports both.

  • Chain-load, don't evict. If a file with the proxy's name is already there and is not ours, Setup keeps it as <name>.chain.dll and our proxy loads it after itself, so ASI loaders and fixes keep working. The diagnostics report what was chained.

  • Nothing written to the game folder at run time. Settings, logs, crash dumps, update backups and markers go to %LOCALAPPDATA%\<mod>\. Existing settings found in the game folder are moved there once.

  • The package describes itself in coop-mod.json: id, name, version, the game's store ids, supported game builds by exe hash, every file with its SHA-256 and destination, the proxy name, the Proton override needed, the homepage and the update source. Setup, the updater, the diagnostics and any manager or script read this one file. Every DLL and exe also carries its version in its Windows file properties.

  • Know who installed it. Setup leaves receipts. Files without receipts that match a release's hashes were installed by a manager or by hand. A file with more than one hard link was almost certainly placed by Vortex, which deploys that way. Exactly which markers each manager leaves is checked when this is built. Setup then shows "Installed by a mod manager" with Play, instead of "Needs attention".

  • The updater defers to the manager. It still checks for new versions. When a manager installed the mod, it shows "Update it in Vortex" with the Nexus link instead of replacing files.

  • One version everywhere. GitHub Releases is the source. Nexus gets the identical zip with the identical version string, named <mod>-<version>.zip, so Vortex's own update check agrees with ours.

  • Scriptable Setup. The same verbs everywhere: status --json, install <game folder> --yes, uninstall, with documented exit codes. This applies to Setup.exe and to install-linux.sh, for Lutris and Heroic install scripts and anyone automating it. On Linux, Setup prints the exact Proton launch option from the manifest.

  • Wrong build or missing pieces never crash the game. Co-op turns itself off and says why in the launcher, as MDK2 already does for an unknown build.

Next: a Vortex game extension and an MO2 basic_games plugin for each game. Both are short, mostly game detection plus "deploy to the game root", and both read coop-mod.json. Once J1 to J6 hold, they are small.

07

Steam Deck and controllers

Everything in this standard works from a controller, and the whole session works on a Steam Deck in Game Mode: press Play in Steam, host or join, play, return to the lobby, all without a keyboard, a mouse or the desktop. Valve's Deck checks ask for the same things: full controller support with the right button icons, the on-screen keyboard when text is needed, and text that is legible at the Deck's 1280 x 800.

The Witness misses the first step today

On a Deck, its README asks players to add the launcher as a non-Steam game with a compatibility setting. In Game Mode, few will get that far. MDK2 already opens its launcher when Play is pressed, because the launcher runs inside the game.

Moving the Witness DLL adds one Proton setting

Proton uses its own copy of Windows DLLs such as winmm unless told otherwise, so a system-DLL proxy needs a DLL override. MDK2 already asks players to type WINEDLLOVERRIDES into Steam. The install can write the same override into the game's own Proton settings instead, so nobody types anything.

Steam can show its keyboard for us

When the game runs from Steam, the Steam API can open the floating on-screen keyboard over a text field and report when it closes. That covers chat, names and invites. Copies from GOG or Epic need our own fallback.

Steam utils API (binding docs)
The Deck looks like an Xbox pad by default

With Steam's default gamepad template, a game sees the Deck's controls as an Xbox controller. A mod that reads that controller works on the Deck, and on most PC pads, with no Deck-specific code. Anyone can also publish a community controller layout for a game in Steam.

Deck Verified criteria

K. Rules

  • Play in Steam opens the co-op launcher, Deck Game Mode included, with no non-Steam shortcut. The Witness game, started without a session from its launcher, hands over to the launcher itself, as it already does for Steam invites. The whole session stays inside the one Steam launch, so playtime, the overlay and the Deck's controls keep working. This needs a live check on a Deck.

  • No launch options to type. The Linux install writes the DLL override for the game's exe into the game's Proton prefix (Wine's per-app DLL overrides in the registry). The launch option stays in the README as the fallback, and the diagnostics report whether the override is in place.

  • Launchers fully work with a pad. Stick or D-pad moves focus, A confirms, B goes back, LB and RB switch tabs, X and Y run the actions shown beside them, and Start presses the primary button (Open lobby, Join, Start game). MDK2's launcher already reads the pad inside the game. The Witness launcher reads the controller itself and drives its own focus.

  • One co-op pad layer, the same in every mod, built on View/Back so it never fights a game's own pad layout. Tap View to ping. Hold View for the player list, and while it is held: D-pad up for the emote wheel (pick with the right stick), D-pad down for chat, D-pad left and right to watch the previous and next player. Each mod checks its game's own pad layout before taking any other button. Checked for The Witness: the game's controller hints use A, B, X, Y, the bumpers, the stick clicks and the D-pad, but never View/Back, so the layer is clear. The game does use the D-pad, so the mod swallows D-pad presses while View is held. MDK2 already uses View/Back for ping.

  • Voice on a pad: open mic with the voice gate is the default when the last input came from a pad. Push to talk can be bound to a free stick click.

  • Text without a keyboard. Chat, the player name and the paste box open Steam's floating keyboard when Steam is running, and our own on-screen keyboard otherwise. A quick-chat wheel (Ready, Wait for me, Over here, Come look at this, Thanks) covers most messages with no typing. On a Deck, joining should rarely need typing at all: Steam friends and the Join list find the game.

  • The right button icons. Hints show pad buttons when the last input came from a pad and keys when it came from the keyboard, and switch at once. Xbox icons by default; PlayStation and Deck icons when the pad type is known.

  • Fits 1280 x 800. Launchers, menus and the HUD fit the Deck's 16:10 screen with text at the I8 minimum. The Witness launcher's fixed window becomes resizable and fills the screen in Game Mode.

  • A published Steam controller layout per game, which maps the Deck's back buttons to push to talk, ping and the player list. It is optional for players, since the default template already works.

  • Tested like everything else. T0: focus navigation, the pad layer and glyph switching, driven by recorded pad states. T1 in the lab: the mods' pad-injection hooks (MDK2 has one) drive a launcher and a co-op action. A real Steam Deck session is the last gate.
